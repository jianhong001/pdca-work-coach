# PDCA 工作教练

**把零散任务，推进成有结果的工作闭环。**

一个陪你明确目标、推进执行、基于真实结果复盘的 AI 工作教练 Skill。先读你的材料，一次只问一个关键问题；信息足够，就一起把事情往前推。

由 **[赵健宏（jianhong001）](https://github.com/jianhong001)** 发起、设计与整理，借助 AI 辅助实现。采用 **[MIT 许可证](LICENSE)**。

[快速开始](#快速开始) · [使用演示](#使用演示) · [作者与方法来源](#作者与方法来源)

## 工作不少，为什么还是觉得没有章法？

- 接到一个任务，却说不清最后要交付什么。
- 计划列了很多，负责人、验收标准和检查点仍然模糊。
- 中途遇到阻碍，不知道该继续、调整，还是停止。
- 复盘讲了很多感受，却没有留下下一次能用的经验。
- 换一次聊天，又要从头解释整个项目。

PDCA 工作教练把这些问题串起来：**目标 → 行动 → 结果 → 学习 → 下一步**。

## 它会怎样帮你？

| 你所在的阶段 | 它与你一起做的事 |
| --- | --- |
| 还没想清楚 | 明确目标、现状、验收方式与限制，找到真正需要解决的差距 |
| 准备开工 | 把想法拆成有负责人、期限、验收标准和检查点的行动 |
| 正在推进 | 协助完成已授权且工具能做的工作，记录真实进展和阻碍 |
| 需要复盘 | 对照目标和证据，判断计划、执行及外部变化的影响 |
| 准备改进 | 梳理保持、改进、停止和开启的行动，沉淀适用的 SOP |

### 四个值得试试的设计

**一次一个关键问题。** 已有材料先读，不重复盘问；关键缺口补齐后就推进。

**从你当前的进度开始。** 新任务可以从计划起步，执行中的项目直接接续，复盘时也不用重填一遍计划表。

**协助行动，也检查结果。** 建议、尝试、本地检查和业务达标分别记录；没有证据的地方保留待验证状态。

**把进度留在工作档案里。** 在有文件权限的环境中，为每项工作维护一份本地 Markdown 档案。下次提供该档案或进入对应项目，就能据此继续梳理。

## 适合什么时候使用？

项目启动、任务拆解、执行受阻、阶段复盘，以及从重复工作中整理 SOP。

任务简单时可以只列一条行动；原因、依赖或职责复杂时，再按需使用鱼骨图、甘特图和 RACI。你不必先学会这些术语。

## 快速开始

### 1. 安装到 Codex

在支持技能安装的 Codex 环境中输入：

```text
请使用 $skill-installer 从 GitHub 安装 jianhong001/pdca-work-coach。
技能位于仓库根目录，安装名称为 pdca-work-coach。
```

安装后在下一轮对话中使用；若技能尚未出现，重新打开 Codex 后再试。已经安装的用户可以直接进入下一步。

### 2. 带着一项真实工作开始

```text
请用 $pdca-work-coach 帮我梳理并推进这项工作。
这是目前的材料和进展：……
```

也可以从中途进入：

```text
请用 $pdca-work-coach 继续这项工作。
先读取我指定的工作档案，结合今天的新进展，判断下一步怎么做。
```

### 3. 留下一份可接续的工作档案

默认保存在项目的 `work-records/` 目录，记录目标、事实与假设、行动、执行结果、复盘和下一检查点。你也可以指定其他位置。

有多个候选档案时，教练会先问清是哪一项工作。没有文件写入能力时，会在聊天中给出可保存的内容，并说明尚未保存。档案按对话和执行结果更新，不会自行建立后台提醒。

## 使用演示

**以下人物、材料和结果均为虚构，仅展示协作方式，不代表真实客户案例或效果测试。**

**你：**“老板让我把客户反馈梳理一下，现在的材料很散。”

**教练：**“这次梳理完成后，你最希望交付一份可查阅的反馈清单，还是一套能持续跟进反馈的流程？”

**你：**“先做清单。明天 18 点前，把这 20 条反馈分好类、标出优先级，再给出三项改进建议。材料已经附上，无法确认的信息先标出来。”

| 阶段 | 演示中的处理 |
| --- | --- |
| P 计划 | 明确交付清单和三项建议，以能回溯原反馈、优先级有依据为验收条件 |
| D 执行 | 在工具与授权允许的情况下整理材料；发现两条信息不全，保留待确认标记和原始来源 |
| C 检查 | 记录“18 条可核对、2 条待补充”，不把信息缺失推断成产品故障，也不声称全部完成 |
| A 改进 | 待补充材料到位并完成核对后，再更新结果；将必要的反馈字段整理为试行收集模板，供下一轮验证 |

最后留下的既有本轮交付，也有下一步：谁补充缺失信息、何时检查，以及新模板是否确实减少了信息缺口。

## 能力与验证说明

这是用于指导 AI 协作的 Skill，能否读取文件、执行操作和保存档案，取决于所在环境的工具与授权。用户的实际目标是否达成，仍需相应的验收证据。

初版已完成技能格式校验和五类人工场景走查：新任务、执行中受阻、缺数据复盘、外部目标变化和跨次接续。人工走查不等同于独立模型测试、真实业务成效验证或第三方认证。
